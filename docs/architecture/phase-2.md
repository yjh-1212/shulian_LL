# Phase 2 实施契约

范围：交易订单及其明细、运输需求、运输供给、发布记录、附件与粮食素材。延续现有 Vue/Element Plus 和红白顶部导航。供需匹配大厅、报价、联运求解仍分别在 Phase4、Phase3 实施。

## 业务规则

- 正式来源仅交易订单；平台按来源系统/原始记录号幂等导入，订单事实不可由需求表单改写。
- 需求从本企业订单明细生成，草稿也占用可运输数量。数据库用整数公斤记录，页面以吨展示，支持3位小数。
- 修改草稿按差额调整占用；撤回发布不释放；取消及草稿删除释放且只释放一次。有效占用必须在订单数量以内。
- 创建/编辑/发布需求仅贸易方；创建/编辑/发布供给仅物流方。平台可查看，不能代替企业发布。
- 需求：草稿→已发布→撤回为草稿；草稿/已发布→取消；已发布修改前必须撤回。发布记录保留版本，定向发布仅指定物流商可见。
- 供给：草稿→已发布→暂停→已发布；有效期结束由后端判定已失效。已发布编辑前必须暂停；失效后可以编辑有效期，重新进入草稿。删除仅草稿/暂停/失效并软删除。
- 有效公开供给以已发布、有效起止时间、服务结束时间、所属主体有效状态共同筛选。外部企业看不到草稿、暂停和失效供给。
- 所有状态动作必须携带版本，过期版本返回409。数量调整、状态变更、发布历史与审计处于同一事务。
- 价格整数分存储；供给参考价格不是最终成交价格。
- 来源与测试数据标记从交易订单/运行环境继承，客户端不得传主体、状态或来源标签来绕过权限。

## 页面与状态

`/supply-demand/demands`、`/supply-demand/supplies`为独立列表。查询区独立于新增工具栏，具备服务端搜索/筛选/分页/排序；抽屉展示上游、状态、字段、可执行动作、发布历史和审计。新增需求先选交易订单明细，再填运输条件。支持失败保留输入、保存锁定、未保存离开确认、详情深链。

附件在对象持久化之后上传，支持图片/PDF、大小/类型校验、鉴权下载与移除。实际货物照片优先于粮食默认示意图；用户原图复制到 public/assets/grain，保留素材内容。

## 数据与验收

使用数据库开发样例订单，不假冒生产订单。区划使用 china-area-data 5.0.1 参考数据（上游注明2019年统计口径），服务端校验三级从属关系，后续正式上线需核对最新区划。来源：[上游数据说明](https://github.com/airyland/china-area-data)。

验收覆盖贸易创建/编辑/发布/撤回/取消、余量与并发超量、指定业务隔离、物流创建/编辑/发布/暂停/失效、公开可见范围、角色越权、附件、图片、刷新与重启持久化、Phase1基础回归。
