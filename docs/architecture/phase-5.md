# Phase 5：合同与联运执行

用户确认：电子签章使用模拟签署；司机小程序在电脑浏览器模拟。所有合同正文、签署页和导出内容显示模拟标识，不生成或声称取得第三方电子签章证书。

## 业务边界

- 承运确认生成合同包，包含主合同和平台附加合同。锁定成交、需求、路线、模板版本快照。平台不能代企业签署。
- 模式 A：主合同双方模拟签署，附加合同双方确认；模式 B：主合同双方、附加合同双方及平台模拟签署。全部完成后合同包生效。
- 草稿提交给承运商确认，可退回；进入签署后内容锁定。变更、终止另建版本，完整保留原版本和签署记录。
- 生效合同由承运商建立联运业务，选择一单制或传统模式。按运输区段分配任务，同一区段累计数量不得超过合同数量。
- 散改集按业务登记批次、到货车辆、集装箱及来源分配，入箱重量不能超过来源车辆净重。各箱可关联不同船舶航次。
- 司机仅看本人任务。流程：接单、到达装货、装货、发车、到达卸货、卸货、回单、完成；信息有误可退回调度。铁路、水运任务由 PC 记录。
- 所有状态改变、签署、档案导出、执行事件都有审计或不可变事件记录。事件按请求键去重。

## 页面与验证

合同四个独立页面，联运服务三个独立页面；司机模拟端使用独立网址 `http://127.0.0.1:5174/` 和独立 HTML 入口、登录会话，原开发地址 `/driver` 自动跳转。PC 与司机令牌不互通。权限及企业归属均由服务端检查。

验证覆盖合同生效门禁、A/B 签署规则、越权、重复任务数量、散改集数量、司机任务归属、状态顺序、单据附件、事件重试与 PC 汇总，以及浏览器完整流程。
