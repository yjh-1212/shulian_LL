# Phase 4：供需匹配实施契约

依据：`docs/requirements/供需管理+多式联运方案+供需匹配大厅.txt` 第4、5章及开发设计规范。沿用现有 Vue / Element Plus、红白顶部导航；`/matches` 仅含需求大厅、供给大厅两个业务视图。精确地址匹配继续暂缓。

## 业务闭环

1. 贸易企业发布完整需求，或选择已关联本企业需求的完整方案后发布。现有 Phase2 发布记录直接进入大厅。
2. 公开竞价允许有效物流企业响应；定向议价仅发布方、指定物流方、平台可见。供给反向对接固定为指定议价，记录供给与来源对象。
3. 物流企业提交全程报价；贸易企业可以接受或还价，物流企业可以接受还价或再次报价。每轮写入新记录，禁止覆盖。
4. 价格由对方接受后进入待确认；贸易企业人工确认承运。确认数量等于所选已接受报价的数量，价格不引用参考价替代。
5. 需求可在发布时允许部分数量承运；完整方案本阶段由单一运营商整体承接。累计确认量不能超过需求总量。取消确认保留原记录，释放已落实量，不自动重新发布。
6. 截止、关闭、拒绝、撤回、重新匹配均保留历史；截止后禁止新报价、议价或确认。已有确认不能通过取消需求绕过。

## 状态与一致性

- 发布状态：ACTIVE → MATCHED / CLOSED / EXPIRED。进度：WAITING、BIDDING、NEGOTIATING、PENDING_CONFIRM、PARTIAL、MATCHED、REMATCH。
- 报价线程：OPEN、ACCEPTED、REJECTED、WITHDRAWN、CONFIRMED；每次动作独立轮次与条款快照。
- 需求保留既有主状态，同时记录匹配阶段、已落实公斤数；发布快照不依赖后续主数据变更。
- 数据库唯一索引限制同一需求一个有效发布。发布、轮次、确认、数量与审计同事务更新；版本校验处理重复点击和并发，409保留输入并提示刷新。
- 金额按整数分、数量按整数公斤存储；元/吨总价由服务端统一计算。超期报价不可接受或确认，自己不能接受自己提出的价格。
- 平台只能查看；物流只能看到自己的报价与议价过程；其他贸易企业可看公开业务字段，不能看报价、订单、隐藏预算或联系方式。

## 界面与恢复

- 紧凑筛选栏：关键词、发布类型、匹配方式、状态、起讫地、粮种、方式、数量区间、发运/服务日期、指定承运主体；URL保存筛选和详情标识。
- 粮食卡片为默认视图，可切换列表；支持分页、排序、选择和导出公开字段。详情抽屉：运输任务、完整方案衔接、响应比选、选中物流商的多轮记录、承运结果。
- 明确展示总价/元每吨、含税口径、承运数量、发运/完成时间、资源、报价期限；完整方案报价需说明是否按原方案承接；调整时必须填写说明，由发布方在议价中确认。
- 关键确认弹窗展示最终物流商、数量和金额。请求中禁用重复提交；失败保留表单，可刷新重试；空态指向发布或调整筛选。
- 宽度不足时筛选折行、抽屉占满可用宽度，报价表横向滚动，保留数量、价格和动作可读性。键盘可操作，控件有明确名称。

## 验收与边界

验证公开竞价、两轮还价与接受、全量/部分确认、取消确认、供给定向对接、完整方案发布、不兼容供给风险确认、超时、并发、跨企业隐私和页面刷新。浏览器验证贸易与物流双方真实操作。只生成后续合同输入，不签合同、不订舱、不派车、不结算。
