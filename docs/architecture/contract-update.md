# 合同需规更新影响

日期：2026-10-01。来源：用户更新的 `doc/合同管理.docx` 及重新提取的 `docs/requirements/合同管理.txt`（《合同管理需求规格说明书》V1.0，已完整阅读）。

## 1. 本次裁决

合同文档已从旧供需重复内容变为独立、完整合同需规。旧“缺少合同需规、仅做最小闭环”结论失效。按开发规范的冲突优先级，更新后的明确合同业务规则优先于规范第13节的过渡假设。

本轮仍实施 Phase 1。此变更更新目标导航、权限、数据/API设计和 Phase 5 范围；本文件不声称合同业务已实现，也不修改 schema 或应用代码。

## 2. 变化摘要

| 原规划 | 新要求 | 影响 |
| --- | --- | --- |
| 合同单列表/详情 | 模板、签署、履约、档案四个二级功能 | 四条独立路由；模板只给平台 |
| 一份最小运输合同 | 一次成交形成合同包，必含主合同与平台附加合同 | ContractPackage 成为签署、生效、归档聚合对象 |
| 只记录双方确认 | 支持电子签章、证书、文件hash和签署模式 | 签章服务接口、回调验签/幂等、文件版本锁定、证据归档 |
| 双方签完生效 | A/B两种附加合同规则 | 服务端检查包内全部必签文件和主体 |
| 平台仅查看合同 | 平台维护模板；模式B签平台自身附加协议 | 需要区分主体/文件类型/动作；禁止代企业签 |
| 简单合同版本 | 模板发布版本不可改；已签合同不能覆盖，变更走补充协议 | 新增模板字段条款、变更前后值及重新签署流程 |
| 运输任务关联合同 | 包+主合同关联，汇总数量/时间/费用/异常/期限 | 履约台账与提醒；费用数据 Phase8补入 |
| 附件记录 | 合同包全证据档案 | 看、下载、导出同样审计；普通业务用户禁止删除 |

## 3. 四个二级菜单与权限

| 名称/路由 | 粮食贸易企业 | 物流运营商 | 平台运营方 |
| --- | --- | --- | --- |
| 合同模板管理 `/contracts/templates` | 页面/菜单/API禁止 | 页面/菜单/API禁止 | 两类模板、复制版本、预览、变量/条款配置、启停/发布日期、签署顺序与A/B模式 |
| 合同签署管理 `/contracts/signing` | 本企业生成包、补授权字段、提交确认、签署、撤回未签 | 本企业确认/退回、补本方签署信息、签署/拒签 | 全量查看、处理异常/版本/作废；模式B签平台方附加协议 |
| 合同履约管理 `/contracts/performance` | 本企业查看、发起/确认变更终止 | 本企业查看、补履约资料、参与变更终止 | 全量态势与提醒；不代双方判承运责任 |
| 合同档案管理 `/contracts/archives` | 本企业查询/预览/下载/导出 | 本企业查询/预览/下载/导出 | 全量权限内查询导出、档案运维 |

三类PC共用一级“合同管理”，四个二级独立业务页面，不能退回成一个页面四个Tab。签署页内部“主合同/附加合同”可用Tab，因为它们属于当前合同包。司机保持无合同后台权限，只能看任务附带只读字段。

建议细粒度权限：`contract-template:read/write/publish`、`contract-package:read/create/submit/confirm/withdraw/reject/void`、`contract:sign`、`contract-addendum:platform-sign`、`contract-performance:read`、`contract-amendment:create/confirm`、`contract-archive:read/download/export/maintain`。代码命名可随现有规范对齐；授权语义不能合并为笼统合同写权限。

## 4. 合同包和生效规则

1. 前置条件是明确已确认承运商与最终成交价；从公开竞价、指定议价、供给反向对接成交均可生成。
2. 同一次成交只有一个当前有效合同包。包内引用两类当前有效模板版本，锁定需求/方案/订单/匹配/议价与成交快照。
3. 主合同记录运输、主体、价格、费用/结算、履约/责任、期限和签署区。系统回填与固定字段不能被企业任意修改；只开放模板允许的补充字段。成交价签前只读。
4. 模式A：主合同双方签署完成 **且** 附加条款双方确认完成；平台无需逐单签章。
5. 模式B：主合同双方签署完成 **且** 附加合同贸易、物流、平台三方签署完成。
6. 整体包满足锁定模式的条件后，由服务端将包置为已生效。缺附加合同或必签方时，不得因为主合同已签而开放任务。
7. 未签核心成交信息变化：作废原包并保留历史，重新生成。已生效核心字段变化：补充协议保留前后值、原因、发起人、生效时间，并按原签署规则签署；涉及平台条款/费时按配置要求平台确认。
8. 合同包状态：草稿、待对方确认、待签署、签署中、已生效、已拒签、已撤回、已作废、已终止。退回修改作为过程/原因记录；文件级签署进度与包主状态分开。
9. 履约状态：待执行、履约中、部分完成、已完成、异常、已终止、已到期；异常不自动形成判责，实际任务结果不覆盖已签正文。

## 5. 字段与 ER/API 增量

实体建议：ContractTemplate、ContractTemplateVersion、ContractTemplateField、ContractTemplateClause、ContractPackage、Contract、ContractParty、ContractVersion、ContractSignature、ContractSignatureEvidence、ContractConfirmationLog、ContractAmendment、ContractAmendmentItem、ContractPerformance、ContractPerformanceAlert、ContractArchive、ContractArchiveItem、ContractFeeAgreement。

关键关系：一个包含主/附合同各至少一份；合同绑定发布模板版本；签章绑定文件版本、签署主体和摘要；附加协议规则在生成时快照锁定；包关联承运确认、主合同、执行业务、履约及档案。已失效包保留生成代次/前包ID，防止重生成覆盖。任务保留包ID与主合同ID。

API规划：

- `/api/contract-templates/*`：仅平台，版本化配置与预览发布。
- `/api/contract-packages/*`、`/api/contracts/*`：成交幂等生成、受控字段、提交/退回/确认、撤回/拒签/作废、包级生效。
- `/api/contract-signatures/*`：发起当前主体签署、附加确认、签章回调、证据查询；回调验签与去重。
- `/api/contract-amendments/*`：变更/补充协议、签署、生效、终止记录。
- `/api/contract-performance/*`：数量/时效/费用/异常/期限聚合与提醒。
- `/api/contract-archives/*`：合同包证据目录、预览、下载、清单导出、访问审计。

模板仅两种类型，每类可以有多版本；同类型原则上只有一个当前有效版本，发布版本不可覆盖，定时生效切换须有审计。预览中的示例值应明确标记，不应写入正式成交或签署记录。

## 6. 与现有规范的边界协调

**发票字段与结算范围。** 新合同需规要求记录发票要求、含税属性、账户、付款条件；这些是合同约定字段。对账结算仍遵循既有需求，不建设发票开具、税务、在线支付、资金托管等流程。平台费单独记录收费开关、收费对象、计费方式、费率/单价、金额、支付节点、开票要求和调整说明，不能混入运输运费假装同一费用。

**平台签署。** 模式B的平台签章是平台作为附加协议当事方的行为，不是替贸易/物流签主合同。平台全量可见也不能越过企业商业确认。需按签署文件、模式、主体身份和操作权限一起验证。

**未生效先组织。** 新C §6.3提到“如业务允许”可配置先组织后补签，但没有要求默认开启。当前继续规范的严格门禁：完整合同包生效后才能下发正式执行任务，不自行引入例外。

**档案报价可见范围。** 新C要求归档“各方报价、还价记录”，D明确物流商不得查看竞争对手私有报价和身份。归档可完整保存证据，但预览/下载/导出必须继承原报价的记录级权限：贸易发布方与平台可查全量，承运物流商只可查看本方过程及最终共同成交事实；不能借合同档案扩大竞价私有数据可见范围。

**法律文本与电子签章。** 本次提供的是产品需求，平台责任条款需取得法务审定正文；只实现其结构与版本能力，不自行将说明示例当最终法律合同。电子签章服务商、授权账户、回调/证书协议尚未提供。允许线下签署文件上传也必须由模板规则配置并保留真实证据，不能用模拟证书宣称完成电子签章。

## 7. Phase 5 验收补充

- 企业账号直接调用模板API返回拒绝；平台模板页面只管理两种类型。
- 发布新模板版本后，旧合同仍显示原模板、原文件、原签章证据。
- 没有成交承运/最终价不能生成；重复请求不重复生成当前有效包。
- 包必须有主合同与平台附加合同；主合同签完但附加未确认不得生效。
- 模式A无需平台签；模式B缺平台签仍停留签署中。平台不能签企业签署位。
- 核心成交字段只读；未签变更作废重建；已签变更追加补充协议并重新按规则签。
- 包未生效时下发失败；生效后任务关联包、主合同、需求、方案和承运商。
- 多任务数量/时效汇总进入履约；异常只做提醒，不能自动产生责任或违约结论。
- 档案完整包含两文件、模板版本、成交快照、签章/议价、变更、履约和费用索引；下载/导出有权限和审计。
- 平台服务费单独展示；合同发票约定不产生开票或支付功能。

阶段拆分保持九阶段：Phase1先纳入正确导航与权限基础；Phase5完成合同模板/包/签署/履约基本台账/档案；Phase7可复用风险提醒基础；Phase8补入已对账、已结算及平台费相关的可追溯索引。不能将未接入签章服务描述为已完成正式签署验收。
