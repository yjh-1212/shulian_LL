# Phase 6 · 全程可视化

## 使用场景与界面

面向粮贸业务员、物流调度和平台运营：从一个运输任务定位当前区段、核对采集数据、查看节点交接，再打开需求、原方案、合同档案或联运执行。

沿用现有 Vue 3 / Element Plus 与红白企业样式。界面主结构为左侧业务链、中间在线高德地图、右侧状态及来源、下方轨迹回放和事件时间轴。地图占主要空间，操作区使用 12–16px 间距、浅边框；区段卡片保持原有 13px 正文。关键运输概念包括运单、运输区段、粮食货量、交接站、港口、司机反馈与签收单据。

颜色采用现有变量：品牌红表示选中与采集轨迹，公路蓝色实线、铁路紫色长虚线、水运青色短虚线。背景与文字继续使用系统中性灰。节点与区段联动是本模块的主要交互，数量按区段统计，明确不相加为唯一货量。

| 路由 | 用途 |
| --- | --- |
| `/tracking/overview` | 运行统计、地图及任务清单 |
| `/tracking/journeys?taskId=...` | 可分享的任务详情与全程链路 |
| `/tracking/alerts` | 确定性规则监测与任务穿透 |
| `/tracking/themes` | 公路、铁路、水运专题筛选 |

## 地图图层与交互

| 图层 | 数据 | 表达 |
| --- | --- | --- |
| 底图 | 高德在线 JSAPI 2.0 平面视图 | 浅底图，保留道路与地名 |
| 计划区段 | 合同引用的原始方案 RouteGeometry / 已核验线路 | 方式颜色与不同线型；公路标注通用道路参考路线 |
| 运输节点 | 原方案或 TransportNode | 起终点与站点按钮，点击查看来源和更新时间 |
| 当前采集位置 | 后端 TrackPoint，排除 HISTORICAL_AIS | 标注设备与采集时间；过期、模拟状态单独提示 |
| 铁路节点观测 | TransportObservation + 可核验节点 | 站点进度，不冒充连续 GPS 位置 |
| 采集轨迹 | 后端按采集时间排序的 TrackPoint | 红色连线，时长或速度异常、设备或来源变化处分断 |
| 回放点 | 同一后端轨迹 | 通过 setPosition 更新单个 Marker；不会重复初始化地图 |

列表选择、链路区段选择和地图位置选择联动右侧详情。每页最多 100 个任务；超过 30 个位置启用 MarkerCluster，选中任务独立突出。刷新保留选择与地图视角，地图控件提供全程适配。卸载销毁地图与定时器。等待底图 complete 后投影图层，回放只在用户操作时启用，并在重绘前清理已有回放标记。

没有可靠几何时只显示节点，不绘制起终点直线。轨迹连线表示采集样本连接，不代表已验证的完整道路走向。轨迹断点也不插值补齐。

## 持久化与来源

- `TrackPoint`：任务、来源类型/系统/记录编号、设备、采集与接入时间、原坐标与坐标系、GCJ-02 归一化坐标、质量、测试标识和内容指纹。
- `TransportObservation`：铁路或 EPCIS 节点、业务步骤、来源时间、原始事件内容、节点主数据关联与内容指纹。
- `TrackingRule`：定位过期、异常停留、停留范围、路径偏离、装卸节点超时阈值与版本。
- 来源记录在任务内唯一；同内容重传返回已接入结果，不同内容返回 409，整个定位批次原子提交。
- WGS84 通过高德正式坐标转换服务处理。转换失败不落入 GCJ-02 图层。
- 司机 POSITION 与 ExecutionEvent 在同一事务内写入 TrackPoint，标注模拟端来源。旧的位置反馈没有明确坐标系，不自动冒充已转换轨迹。

## 接入接口

关联承运商使用现有 PC 登录令牌以及 `service:write` 权限进行接入。接口均先校验任务归属。没有新增公开写入接口，也没有配置第三方 GPS/AIS/铁路账号。

| 接口 | 内容 |
| --- | --- |
| `POST /api/tracking/tasks/:id/positions` | 1–100 个 GPS、AIS、历史 AIS 或测试模拟点 |
| `POST /api/tracking/tasks/:id/rail-events` | 铁路到发、装卸、交接观测 |
| `POST /api/tracking/tasks/:id/epcis-events` | ObjectEvent / OBSERVE 子集 |
| `GET /api/tracking/tasks/:id/trajectory` | 按时间筛选后的 GCJ-02 轨迹与断点 |
| `GET /api/tracking/tasks/:id` | 计划区段、轨迹、物流事件、风险、单据及来源链接 |
| `PUT /api/tracking/rules` | 平台维护阈值，带版本冲突校验 |

EPCIS 接口仅接收约定的 ObjectEvent 子集，不宣称完整 EPCIS 2.0 Capture/Query 兼容。EPC 列表必须绑定本任务 `urn:grain:task:<id>` 或所属箱号 `urn:grain:container:<boxNo>`。外部节点观测归集进时间轴，保留与任务执行反馈的区别；不会绕过前序数量交接、凭证和签收规则改写任务状态。

## 权限与真实数据

粮贸与物流主体仅能查看本企业参与的合同业务，平台查看全局。服务端先按合同参与方过滤，再执行搜索、分页、聚合、地图数据与轨迹查询。司机令牌仍隔离于 PC。

接口默认排除测试业务；开发页面提供明确的“包含测试样本”开关。生产环境忽略该参数并强制排除测试记录。模拟点/模拟观测仅能导入开发测试业务。AIS 接入来源的历史记录不能覆盖当前位置，近期上报也显示来源及时间，不宣称系统已经连接实时船舶供应商。

## Phase 6 与后续范围

本阶段完成位置与节点归集、地图、回放及基础监测。预警包括缺少定位、过期定位、到达约定超期、装卸超时、异常停留、参考路径偏离及执行异常。ETA 返回待预测；没有用计划到达时间冒充预测结果。

Phase 7 再接入 ETA 模型、预测更新记录、港口拥堵、气象/海况与政策风险，以及后续通知策略。高量业务的分库、轨迹归档和异步风险计算也需按实际供应商与吞吐量扩展。
