## 2. 使用者、任务和领域表达

平台管理员需要核对主体、用户、角色及其访问范围，并能追溯变更；贸易企业和物流运营商需要确认自己当前的主体身份及可用业务入口。司机仅使用司机小程序，不能通过 PC 登录后进入业务后台。

业务词汇：粮食批次、运输需求、承运主体、联运方案、贸易企业、运单、合同、对账。视觉来自实际领域的红色业务印章、白色单据、浅灰工作台、粮食金色和水运蓝色。后两者用于后续货物图片及运输方式编码，不能变成全局装饰色。

产品识别点是“当前主体 + 角色 + 有权限的业务入口”，并贯穿顶栏身份区、工作台欢迎区、账户详情、角色数据范围和操作审计。首页按待办和可执行入口组织，不做大屏；基础管理按用户/角色/主体的身份和状态扫描，不以存储表名组织页面。

这是基于需求的设计判断，尚无访谈、任务观察或真实使用频次证据。不得把它表述为已验证的用户心智模型。

## 3. 视觉系统

### 3.1 颜色

在全局主题定义以下语义变量，并统一映射 Element Plus 主题变量。页面组件不各自硬编码颜色。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--brand-primary` | `#E52B2F` | 主按钮、当前导航、关键业务强调 |
| `--brand-primary-hover` | `#D52227` | 主按钮 hover/active |
| `--brand-primary-soft` | `#FFF2F2` | 轻选中背景 |
| `--text-primary` | `#1F2329` | 主内容 |
| `--text-secondary` | `#646A73` | 辅助内容 |
| `--text-placeholder` | `#A0A5AD` | 禁用/占位；不用作必要说明 |
| `--page-bg` | `#F5F6F8` | 页面底色 |
| `--surface` | `#FFFFFF` | 顶栏及内容区域 |
| `--border` | `#E7E9EE` | 边界 |
| `--divider` | `#EEF0F3` | 次要分隔 |
| `--success` | `#18A058` | 成功状态辅助色 |
| `--warning` | `#F59E0B` | 待处理辅助色 |
| `--danger` | `#E03131` | 错误/失败辅助色 |
| `--info` | `#2F80ED` | 进行中辅助色 |

语义色只作辅助。状态永远有中文文字；浅绿/橙色图标或底色不能独自承载含义。小字标签可使用深色正文配浅色底，避免直接使用低对比度浅色文字。焦点用至少 2px 可见轮廓，不能只在红色边框上做细微色差。

### 3.2 尺度与组件

- Header 64–68px，Breadcrumb 40–44px；主要内容外边距 24px，1440px 以上可用 28–32px。
- 4px 间距基准；控件间距 8–12px、区块间距 16–24px；白色内容面少阴影、6–8px 圆角。
- 表格默认 48–52px 行高；长名称允许两行或省略并能通过键盘/详情读取完整值；ID、时间和计数使用等宽数字。
- 中文字体优先系统中文无衬线（PingFang SC / Microsoft YaHei 等）；正文 14px、次要内容 12–13px、区块标题 16px、页面标题 20px/600。用户缩放不得被禁止。
- 列表保持白色数据面和轻边界，避免多层有大内边距的卡片包住表格。表头、工具栏、数据和分页视觉连续。
- 新建按钮位于列表工具栏右侧；筛选区只包含条件、搜索和重置。行级“查看/编辑/删除”等放“更多”菜单，身份名称可直接进入详情。
- 使用 Element Plus 的表单、按钮、表格、分页、对话框、抽屉、菜单、选择框等统一行为；采用统一 SVG 图标，禁止用 emoji 充当业务图标。
- 不采用暗黑霓虹、玻璃拟态、全页大红底或装饰性数字大屏。粮食图片仅在后续货物/匹配语境使用，不在用户管理表格中装饰。

## 4. 应用壳层与动态 Overflow

### 4.1 导航结构与权限

数据库驱动的一级顺序： 首页 → 供需管理 → 联运方案 → 供需匹配 → 合同管理 → 联运服务 → 全程可视化 → 对账结算 → 数据服务 → 系统管理。

按 2026-10-02 用户调整：粮食贸易企业将“供需管理”替换为直接进入需求列表的“运输需求管理”，不显示运输供给管理入口；物流运营商替换为直接进入供给列表的“运输供给管理”。企业端面包屑直接显示对应管理页，平台端保留供需分组。导航仍按账号实际权限过滤；贸易企业不能通过管理页网址进入运输供给管理。

同日供给表单调整：运输企业名称取登录所属企业并只读；可承运数量合并为下限和上限；起运、目的地区选择到市级。移除供给名称、详细地址、途经节点、独立承运量字段、资源类型、服务时间、有效期、预计时效和计价单位。保留运输方式、适运粮种、选填资源说明、配套服务和联系补充。装载形式分为散货（元/吨）和集装箱（20GP、40GP 分别按元/箱报价），所选装载形式的报价必填。新供给发布后持续展示，暂停或终止后下架；列表、详情、导出和匹配大厅使用相同的数量范围与报价。历史时间窗口和报价来源保留，旧版接口继续兼容。

系统管理仅平台运营方，子项为用户管理、角色权限、数据字典、合作主体、日志管理。每个子项独立路由；禁止将五个独立管理模块塞进同页 Tab。日志类型可在同一日志页用 Tab，因为它们属于同一查阅任务。AI 不占一级导航，放右下角有文字说明和可访问名称的悬浮入口。

流程为：获取登录身份与授权菜单 → 过滤无权限项及空父项 → 排序 → 宽度分配。路由守卫与服务端授权必须同时存在。已规划但本阶段未开通的业务不得以可点击空壳页面出现；如果为说明导航结构而呈现，应禁用并明确标注“后续阶段开通”。阶段菜单必须真实反映后端配置。

顶栏显示当前用户、主体和退出。身份切换只对服务端授权的主体开放；没有切换能力时提供退出后重新登录，不使用前端下拉框伪造切换。面包屑保留当前位置；浏览器后退和刷新可还原页面。

### 4.2 可实现的宽度算法

1. 使用 `ResizeObserver` 监听 header、品牌区、用户区和候选菜单测量区；字体完成加载和授权菜单变化后重新计算。
2. 测量真实菜单宽度，包括图标、中文标签、下拉箭头和水平内边距。测量副本不可被键盘或辅助技术重复访问，也不可参与可见 header 的宽度循环。
3. 首页固定保留；品牌、完整系统名称、用户区和间距先扣除。先按不显示“更多”计算一次；全部可放下时直接显示全部，“更多”隐藏。
4. 若放不下，预留“更多”真实宽度，再把可收纳项按 `overflowPriority` 从低保留优先级开始移入 overflow；相同优先级按 `displayOrder` 从右向左收纳。默认优先收纳顺序为系统管理 → 数据服务 → 对账结算 → 全程可视化。
5. 顶部和“更多”内部均按 `displayOrder` 显示。重新计算始终从全量已授权菜单开始，扩大窗口后自动恢复，不能只从上一次顶部结果继续删除。
6. 若当前路由命中 overflow 中任何父/子项，“更多”显示红色激活文字及下划线。路由匹配依据菜单 route/name 或其后代关系，避免字符串前缀误匹配。
7. 一次 `requestAnimationFrame` 合并测量和更新，使用稳定宽度及少量舍入余量防止来回抖动；卸载时断开 observer。不得靠压缩汉字、固定“更多”菜单清单或 Header 横向滚动完成适配。

PC 验收重点为 1280、1440、1920px；增测 1024px 和大字号以发现固定宽度假设。极窄屏/400% 缩放时，保持上下结构：品牌和用户区换为上下排列的两行顶栏，菜单集中为“首页 + 更多”；完整系统名称允许换行而不压缩字体。筛选区和表单改单列。数据表自身可带标明名称的局部横向滚动区，页面整体和 Header 不横向滚动。关键字段及行操作在窄屏保持可达。

下拉必须支持点击、Enter/Space 展开、Escape 关闭和焦点返回；普通导航使用链接/披露语义。如使用 Element Plus 菜单语义，必须完成其方向键及焦点行为验收。悬浮 AI 不能遮挡分页、抽屉保存按钮或键盘焦点。

## 5. 通用状态与服务边界

| 状态 | 页面反馈 | 可继续的动作 |
| --- | --- | --- |
| 首次加载 | 保留顶栏、标题与查询区域，主体 skeleton | 不误显示 0 或“暂无数据” |
| 正常数据 | 服务端总数、分页、状态和更新时间 | 查询、查看及已授权操作 |
| 数据确实为空 | 说明当前对象尚无记录 | 有创建权限时引导新增；只读时给返回/刷新 |
| 查询无结果 | 明确“未找到符合条件的记录” | 重置查询，不诱导重复创建 |
| 首次加载失败 | 原因、重试；保留查询条件 | 重试或返回工作台 |
| 刷新失败 | 保留上次成功数据并标记更新失败/更新时间 | 手动重试，不把旧数据说成实时 |
| 字段错误/409 冲突 | 字段内具体原因，保留全部有效输入 | 修正后重试；冲突时查看最新记录 |
| 401 会话失效 | 尝试一次受控刷新；失败后进入登录并保存安全的站内返回路径 | 重新登录；不向其他用户恢复敏感草稿 |
| 403 权限变化 | 说明无权访问，提供工作台入口 | 刷新身份/返回；不渲染受限记录 |
| 404 真正不存在 | 明确记录不存在/已删除 | 返回原列表；网络错误不能冒充 404 |
| 写入中 | 按钮 loading，阻止重复提交 | 安全取消编辑仅在提交前可用 |
| 写入成功 | 服务端结果更新列表及详情；真实成功反馈 | 留在上下文或查看记录 |

搜索、筛选、排序、分页和数量必须覆盖服务端完整授权数据集，不在当前页数组上筛选冒充全量。URL 保存 `q/status/type/sort/page` 等可分享查询状态，刷新/后退不丢失条件；搜索提交/重置后页码回到 1。筛选值变化应可见，旧响应不得覆盖新请求结果。

批量操作与单条操作复用同一授权及服务规则；选择范围必须明确为当前页或全部匹配，不能把当前页说成全部。若提供“全部匹配”，服务端按同一查询重新获取授权集合。部分失败列出失败对象及原因，只重试失败项。只读日志不提供批量修改或删除。

新增/编辑后必须等待服务端确认；角色权限、账号状态和主体状态不使用乐观成功。前端只能展示后端状态与 allowedActions，不自行宣布核心业务结果。所有开发样本显式显示“开发样例”，且记录持久化 `isTestData=true`。

非敏感长表单草稿若持久化，使用服务端草稿并按当前用户/主体/对象隔离；密码、Token、密钥不持久化到浏览器草稿。Phase 1 短表单至少保留失败输入，并在有改动的关闭/路由切换时确认放弃；浏览器刷新提示仅是兜底，不能宣称实现了持久草稿恢复。

## 6. 页面契约

### 6.1 登录与账户安全

- 入口 `/login`；仅有一个突出“登录”主按钮。账号、密码有常驻标签；允许粘贴和密码管理器，使用合适的 autocomplete。
- 空字段及格式错误在字段下方显示；账号/密码错误用统一文案，不暴露账号是否存在。保留账号，密码不写日志、不进入 URL。
- 点击登录进入提交中，禁止重复请求；成功后获取当前用户、主体、角色、菜单和权限，再进入合法站内返回地址或工作台。
- 停用、锁定、过期会话、网络错误与司机端不支持 PC 登录均有明确说明及返回路径。服务端负责限制和状态检查。
- 用户菜单提供修改密码、退出；密码变更表单区分原密码、新密码、确认密码，按实际服务端密码策略显示约束。重置密码属于平台管理授权动作；不得伪造“发送短信/邮件”成功。
- 退出后清理身份和数据缓存；浏览器后退不恢复受保护数据。跨账号登录不能继承上个用户的列表/草稿。

### 6.2 工作台

- 标题“业务工作台”，显示当前用户、主体、角色和数据范围说明。
- 平台工作台优先真实的用户/主体基础管理统计、最近审计和快捷管理入口；贸易企业与物流运营商显示各自身份、可用入口及与身份相符的帮助信息。
- 需求/匹配/运输/账单等业务尚未实施时明确“当前阶段尚未接入”，不显示看似真实的 0 值、增长率、伪实时地图、随机在途任务。
- 已实现指标由后端聚合；读取失败显示失败，不能落到全零默认值。真实零值与未接入区分。
- 最近操作显示业务动作、结果、对象、时间；有日志权限时可穿透日志页。刷新不自动打乱正在阅读的数据。

### 6.3 用户管理

- 独立路由建议 `/system/users`。查询：账号/姓名/手机号关键词、主体、角色或身份、状态。主操作“新增用户”。
- 列表首屏：账号与姓名、所属主体、身份/角色、账号状态、最近登录、更新时间、更多；显示总数和分页。
- 新建/编辑：账号、姓名、手机号、可选邮箱/部门、主体、角色、状态；初始密码/重置与普通资料编辑分离。角色和主体选项由真实 API 提供，仅列允许组合。
- 角色不可把司机变成 PC 业务身份；数据范围的含义在选择时展示，不能只显示抽象代码。
- 更多包含详情、编辑及服务端允许的启停/重置密码等操作。停用/重置先明确对象和影响，再确认提交；有依赖的删除按后端规则拒绝并说明。
- 成功后数据库记录可刷新、重启后仍可查；详情与列表一致；创建人/修改人及时间可查看。最后一个平台管理账号等保护规则以服务端实现为准，并在拒绝时说明。

### 6.4 角色权限

- 独立路由建议 `/system/roles`。按名称/编码搜索，按身份类型过滤；显示角色名、类型、数据范围、授权摘要、状态。
- 权限编辑按菜单、页面/操作和数据范围分组；选中项有文字标签，不仅用图标。子权限与父导航的关系要明确。
- 保存前可查看变更摘要，显示角色和影响范围；点击保存后等待后端确认。无权授予的能力不可提交。
- 明确提示“重新登录后按新权限生效”或实际生效策略；验收必须使用目标账号重新登录证明，不以编辑页面打勾作为成功依据。
- 系统内置角色是否能删除由服务端保护规则控制，受保护操作应显示原因。平台全量查看不等于替企业确认承运、签合同或确认对账。

### 6.5 合作主体

- 独立路由建议 `/system/entities`。关键词按主体名称/编号/信用代码，过滤主体类型和合作状态。
- 列表：主体名称/编号、类型、统一社会信用代码、联系人/电话、合作状态、更新时间及更多。
- 表单按基础信息、联系信息分组；物流运营商适用时扩展区域/运输方式/能力。状态采用需求口径“待启用、正常、暂停、终止”，服务端维护状态值。
- 唯一编号/信用代码冲突给字段错误；暂停/终止说明对关联用户/业务的真实影响。已被业务引用时不可通过前端删除按钮破坏关联。
- 资质附件与有效期若尚未实现，应列为后续能力，不能展示无持久化上传控件。

### 6.6 数据字典

- 独立路由建议 `/system/dictionaries`。按分类/名称/编码查询；显示类别、编码、中文标签、排序、启停状态。
- 新增/编辑校验分类内编码唯一。对正在被业务引用的字典值优先停用，不能改码后静默破坏历史语义。
- 运输方式/货物/装载/风险/单据/结算/数据产品分类来自服务端字典。关键业务状态字典标签可维护不代表允许任意新增状态迁移，流程仍由后端规则约束。

### 6.7 日志管理

- 独立路由建议 `/system/audit`。同页按“登录日志 / 操作日志 / 数据变更 / 接口日志”切换已真实支持的类型。
- 查询包括时间范围、关键词、用户/主体、模块、动作和结果；时间默认明确时区，展示本地时间 Asia/Shanghai。
- 列表：时间、操作者/角色/主体、模块/对象、动作、结果、requestId；详情展示经脱敏的变更前后、IP/终端和失败原因。
- 只读日志无新建、修改、删除按钮；日志自身应不可被普通业务用户修改。敏感字段只记录字段名/掩码，不记录密码、JWT、大模型密钥、高德安全码。
- 搜索无结果与读取失败区分；请求失败仍可通过 requestId 排查。若导出开放，必须按相同权限和完整筛选条件由 API 生成真实结果。

### 6.8 AI 悬浮入口（Phase 1）

三类 PC 身份有入口，司机账号无入口。按钮可用键盘激活，抽屉展示当前主体/页面上下文及“智能体能力将在后续阶段接入”的明确状态；可关闭并返回原焦点。没有接入真实业务前不提供假对话回答或可提交但无服务的输入框。后续 AI 调用继承服务端权限，业务最终确认仍由人执行。

## 7. 可观察验收要求

每一项以 pass / fail / blocked / not applicable 记录到 `docs/acceptance`，附浏览器版本、URL、身份、数据样本、步骤、观察结果和截图/断言。以下是验收标准，不是通过声明。

| 编号 | 条件与操作 | 必须观察到的结果 |
| --- | --- | --- |
| UI-01 | 三类 PC 账号分别登录 | 显示正确主体/角色；授权导航有差异；企业没有系统管理/数据服务 |
| UI-02 | 企业直接请求平台管理路由及 API | 页面拒绝并可返回；API 真正返回拒绝，不泄露记录 |
| UI-03 | 平台用户在 1440 → 1280 → 1920px 调整窗口 | 低优先项动态进入更多并恢复；Header 不横向滚动；保存两种规定宽度截图 |
| UI-04 | 打开更多内子路由并刷新 | 子项、更多激活正确；面包屑和当前位置一致 |
| UI-05 | 保存角色权限后目标账号重新登录 | 菜单/API 权限按修改结果执行；旧缓存不复活 |
| UI-06 | 新增/编辑用户、主体、角色、字典后刷新及重启 API | 记录和变更依然存在；列表详情一致；有操作留痕 |
| UI-07 | 触发空数据、无结果、500/断网、403、404 | 各状态区分；失败不伪装为空或 0；可重试/返回 |
| UI-08 | 错误表单提交、重复点击、关闭脏表单 | 保留有效输入、有具体错误；不重复创建；放弃修改有保护 |
| UI-09 | 查询后分页/排序/后退/刷新 | 查询作用于授权完整数据集；URL及记录总数一致；条件恢复 |
| UI-10 | 键盘完成登录、菜单、表单、更多操作、关闭抽屉 | 所有动作可达；焦点清晰、不被固定区域遮挡；关闭返回触发点 |
| UI-11 | 200% 文字放大/320 CSS px 等效重排 | 标签、错误、提交按钮不裁切；Header/页面不横向溢出；表格可局部滚动 |
| UI-12 | 退出、令牌过期、跨账号重登 | 安全回到登录；后退不能查看旧账号数据；未泄漏旧缓存 |
| UI-13 | 查看日志及网络响应 | 有实际操作者/主体/动作/结果/requestId；无敏感明文 |
| UI-14 | 以 reduced-motion 和正常模式打开菜单/抽屉 | 含义和操作不依赖动画；减少动态效果后任务仍可完成 |

普通文字目标对比度至少 4.5:1，适用的控件/图形边界至少 3:1。WCAG 2.2 AA 最小目标为 24×24 CSS px（有适用例外）；本项目触控入口尽量 44×44px，不把 44px 错称为 AA 一刀切要求。自动检测只能证明执行到的规则，屏幕阅读器实际朗读、完整焦点旅程和 WCAG 符合性尚需单独取证。

## 9. 联运求解工作台补充（2026-10-02）

输入条件位于上方，下方左地图、右方案。支持需求地址带入和直接输入，按可靠性、成本、时效比较，分段详情包含费用和公开路线来源。需求日期和数量沿用原需求约束；手动发运时间必须晚于当前时间。

原始地址先匹配业务节点，再调用地理编码及 POI 查询。仅取得区县位置时要求确认装卸点。公路使用真实道路几何；铁路、水运采用明确标注的走廊示意。可靠性为模型评分，模拟费率和候班不能作为实时报价及订舱承诺。

求解页不展示供应商。选择方案后公开发布到供需大厅，保存完整分段快照并等待运营商整体报价。手动方案发布需关联本企业订单；订单余量占用、需求创建、方案选择和发布在同一事务中完成。超量、过期、跨企业、旧版本及重复发布由后端校验。
