# 业务初始化资料来源

## 资料性质

这批记录是按用户明确要求生成的业务初始化资料，**不是已核验的现实交易**。系统页面使用正常业务名称，来源标记保留在数据、合同草案和初始化清单中，供核验和后续真实资料替换。

| 资料 | 来源及处理 |
| --- | --- |
| 运营平台 | 保留 `platform`、原管理员账号与密码，显示名称为辽粮运营中心 |
| 粮食企业、物流企业 | 生成合理的运营档案；不使用公开企业名称冒认已注册、已合作或已报价的主体 |
| 司机、车辆 | 生成姓名与资源编号供业务结构初始化；不提供身份证号、驾驶证号、个人电话或已核验车辆登记信息 |
| 船舶、航次 | 生成运营档案；MMSI 留空，未声称接入真实 AIS，也未将任意数字填作实际船舶身份 |
| 交易、运输需求、报价、承运衔接 | `sourceSystem=BUSINESS_INITIALIZATION` / `sourceType=INITIALIZATION`，业务条款和数量为合理生成值 |
| 合同 | 16 份草案，`status=DRAFT`；正文写明来源与未生效状态，不创建任何签章记录 |
| 运单、任务、状态与回传数量 | 用于初始化业务链。`TransportTask.feedback`、事件和清单保留来源。数量和状态没有原始凭证佐证，不能替代运输证明 |
| 费用与账单 | 参考费用与草稿账单，不能作为真实债权、收付款或发票依据；凭证待实际上传 |
| 定位点 | 沿公路、铁路基础设施与沿海航路参考几何生成，`sourceType=INITIALIZATION`、`dataQuality=INITIALIZATION`；不是北斗、GPS 或 AIS 实测记录 |
| 港站 | 项目已有的高德 POI 查询结果，保留地点 ID、GCJ02 坐标、查询来源和时间；并不意味着该站港已确认承运某批粮食 |
| 公路路径 | 匹配实际 `AMAP_V5_DRIVING` 缓存，始末偏差须在 350 米内；缺失则拒绝初始化，不回退为跨城直线 |
| 铁路几何 | 从 OpenStreetMap 普通铁路的实际连通节点拼接；保存线路和 way ID、WGS84→GCJ02 处理、原始数据散列和归属信息；属于公开基础设施走向参考 |
| 水运几何 | 按公开营口—华南业务流向生成沿海航路参考，经海上走廊与珠江口连接港口；不是承运方 AIS 航迹或官方海图 |
| 公路参考价格 | 通用 0.36、大豆 0.40、稻谷 0.38 元/吨公里；是初始化估算，供求解器接驳比较使用，成交价待确认。没有将其标为真实市场报价 |

`isTestData=false` 用来将这些资料纳入正式页面的数据范围，**不表示来源已经核验**。核验状态保留为 `UNVERIFIED_BUSINESS_RECORD`。既有明确测试记录可软归档，但不删除历史资料，不覆盖非测试主体资料。

新增司机账号的密码随机生成，初始化工具不输出密码。实际使用前由平台核验司机身份、关联所属企业并通过账号管理完成密码设置。原管理员、贸易企业、物流企业与原司机账号的 ID、角色和密码保留。

16 条运力在每种路线中分别提供 2 条散货、2 条集装箱资料。省市区以系统区域字典的行政编码保存，供双向匹配读取。报价字段采用现有接口的 `quantity`、`price`、`unit=PER_TON`、`priceCents`、`totalCents`、含税及承运能力等结构。公开发布的预算保持私有，快照只保存需求字段，不夹带其他运营商的报价或合同参与方资料。业务说明使用普通文字，技术来源保留在快照、条款、事件及审计中。

生成回放沿路径累计距离分配时间，按 20 米容差保留转弯，再加密至点间最多 1500 米、通常最多 4 分钟。每个任务超过 5000 点会拒绝初始化，禁止截断末段或退回首尾直线。完整原始几何单独保存。在途公路车辆使用不同进度，已完成车次仍保留完整回放轨迹；道路任务数量为零，完成后的计量字段保留初始化来源。

OSM 几何使用 `© OpenStreetMap contributors (ODbL)` 归属标记。地图展示这些铁路几何时，应保留可访问的 [OSM 数据归属链接](https://www.openstreetmap.org/copyright)。该标记不表示 OSM 或铁路运营方认可本系统生成业务。

原始铁路数据放在 `tools/fixtures/geometry-references/`：东北区域、京哈/京广等主线、广州节点和京津接续区域四份响应。`tools/build-business-route-geometries.cjs --rebuild` 可从这些文件重建参考路径，不读取私有定位接口，也不写数据库。

## 旧资料处理边界

只读审计输出 `docs/acceptance/business-data-fixture-audit.json`。当前明确的候选包括 11 个历史测试/验收主体，其中 2 个没有测试标记、但同时具有 `sample-group` 组织及 `验收粮贸企业-*` 名称的已知验收主体；另有 4 个浏览器/Phase8 验收产品、2 个仍启用的模拟船舶和 31 条明确测试价格。

加上 `--archive-tests` 后，测试及已知验收主体和其业务仅做关闭、停用或软归档；旧价格停用，验收数据产品设为 `OFFLINE`；21 个明确的验收合同模板设为 `ARCHIVED`，保留原附件与状态审计。五个 `GDS-*` 业务产品明确保留，任何未知真实主体和产品不因名称相似而归档。保留八个原账号、密码、角色和所属关系；原企业账号显示名改为正常业务称呼，原司机改为生成姓名。档案与价格变动使用含 `BUSINESS_INITIALIZATION` 来源的审计记录，原值可查。

合同模板初始审计共 21 条带明确模拟、演示或验收身份的模板，15 条 `PUBLISHED`、6 条 `DRAFT`。模板模型的 `status` 是字符串，没有独立归档日期字段或模板归档接口。审核后初始化工具将这些明确候选软归档为 `ARCHIVED` 并保留来源审计，合同 API 默认过滤该状态；正文、原版本和已有附件保留。

## 运行和保护

```powershell
# 仅生成清单，读取数据库但不写业务表
node tools/initialize-business-data.cjs

# 审核清单后，先做一致性备份再初始化；保留历史测试记录
node tools/initialize-business-data.cjs --apply

# 同时软归档具有明确测试标记或已知验收身份的历史资料
node tools/initialize-business-data.cjs --apply --archive-tests
```

初始化前调用 SQLite `VACUUM INTO`，备份位置在 `.local/backups/business-initialization-*`，包含备份散列清单。实际初始化输出 `docs/acceptance/business-data-initialization.json`，预览输出 `docs/acceptance/business-data-initialization-preview.json`。预览与几何构建不写业务数据库；只有明确加上 `--apply` 才初始化业务。

幂等规则：按固定业务 ID 创建；存在的运单、任务、运力和已维护档案保持原值，不重置业务状态、密码或金额。非测试主体使用同一 ID 且已被用户改为其他名称时，初始化工具拒绝覆盖。既有测试档案的名称改为正常业务名称，仅在有明确测试标记时执行。

初始化业务的生效合同、凭证、资质、定位接入和费用核验工作，应在正式资料录入后完成。不能把生成资料作为法律证据，不能把参考轨迹视为真实即时位置。

## 初始化时间校准

2026 年 10 月 3 日的首次初始化使用了 `02:00:00Z` 的固定时间基准，实际入库在 `12:09Z` 附近完成。已通过 `tools/calibrate-business-initialization-time.cjs --apply` 统一校准到 `2026-10-03T12:32:42.845Z`，平移差值为 `37,962,845` 毫秒。原始基准保存在初始化清单的 `originalProvenance` 和不可改写的原审计记录中。

校准覆盖需求、运力、议价、合同草稿、运单、阶段、任务、计量回传、费用及参考轨迹的业务时间；16 份初始化预测和 2 条初始化提醒的最新计算或检查时间同步刷新。坐标、数量、金额、真实入库时间、公开路网查询时间、价格有效年度、签章及其他账号资料保持原值。定位来源仍为 `INITIALIZATION`，不是北斗或 AIS 的实际接入。

工具默认只读，加 `--apply` 后先使用 SQLite `VACUUM INTO` 备份，再在一个事务中完成校准。固定审计 ID `business-init-v1-time-calibration-v1` 使重复运行直接返回 `ALREADY_CALIBRATED`，不会二次平移。来源审计、差值及备份路径记录在 `docs/acceptance/business-data-time-calibration.json`；逐表与备份比对结果记录在 `docs/acceptance/business-data-time-calibration-verification.json`。后续新库初始化使用运行时的当前时间，已存在的固定业务 ID 继续跳过，保持已有业务状态。
