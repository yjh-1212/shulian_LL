# 腾讯云功能与流畅度检查

检查日期：2026-10-06。地址：http://124.222.207.72:8080/

## 结论

使用管理员、粮食贸易商和物流运营商账号检查了 42 个页面。线上主要问题是跟踪数据下载超时、业务列表包含大量详情，以及小图体积过大。底图可以正常显示，当前智能体首页可以正常打开。

本次修复已完成本地构建和数据库副本验证，尚未部署到腾讯云。线上检查未提交运输、合同、费用或结算操作。真实问答使用数据库副本，并按已有授权调用 DeepSeek；测试对话仅保存在副本。

## 已确认的问题与修复

| 优先级 | 问题与证据 | 本次处理 |
| --- | --- | --- |
| 高 | 跟踪列表约 19.7 MB；管理员专题视图、贸易商全程跟踪、承运商专题视图出现“请求超时，请重试” | 全程列表先传摘要，选中运单再读取完整轨迹；专题只传对应运输方式；轨迹使用紧凑格式并原样还原坐标、时间、车辆身份和断点；增加 JSON 压缩 |
| 高 | 合同列表约 3.8 MB，浏览器接口约 10.7 秒；联运列表约 4.15 MB，约 11.6 秒 | 列表只传展示字段，合同文件、完整费用和执行资料在打开详情时读取 |
| 中 | 48 像素粮种小图使用 1.8–2.2 MB PNG；部分图片下载超过 20 秒 | 使用原图生成 160 像素 WebP 缩略资源，每张 5–9 KB；AI 标识改用已有 WebP |
| 中 | 部分运输、费用、结算操作直接调用 HTTP 环境缺少的 `crypto.randomUUID()` | 统一使用支持 HTTP 的随机请求编号，保留重复提交保护；浏览器中验证缺少该方法时阶段详情正常打开 |

| 中 | 所有账号工作台始终显示“晚上好”：中文小时字符串含“时”，转换数字失败；问候语也未随时间更新 | 读取北京时间的数字小时，统一各账号问候语；每分钟更新，返回页面立即更新 |

## 已有腾讯云服务器升级

使用 `ll_dist/liaoliang-performance-fix.zip`。

1. 用当前运维方式备份线上数据库、上传附件与配置，然后停止当前项目进程。
2. 解压更新包，将 `liaoliang-server/` **里面的文件**覆盖到当前应用根目录，即包含 `package.json` 的目录。更新包只包含程序、图片和说明，不含数据库、上传附件或密钥配置。
3. 使用当前启动命令或进程管理工具重新启动该应用，再在浏览器强制刷新。
4. 检查合同履约、联运服务、全程跟踪与专题视图；确认 Network 中 JSON 响应包含 `Content-Encoding: gzip`，跟踪请求包含 `compact=true`，没有持续加载或超时。

数据库结构和依赖没有变化，无需初始化数据库、重置账号或重新安装依赖。完整的 `ll_dist/liaoliang-server.zip` 同步更新，适合新服务器安装；已有服务器使用上述更新包以保留线上业务数据。

本次完整包中司机账号 `driver` 已设置为指定密码。已有服务器需要单独初始化该账号，更新包内的 `DRIVER-ACCOUNT.md` 包含命令；不要覆盖正在使用的数据库。

## 后续值得继续优化

- 跟踪服务仍会计算符合主体权限的多个运单再筛选分页。本地公路专题计算约 2–3.5 秒；业务量增长后，应把筛选和分页前移，再只计算当前页的轨迹与风险。
- 专题车辆侧栏按运单分页，当前公路视图可能有数百辆车。可进一步给车辆列表增加分页或虚拟滚动。
- 公共前端依赖包约 1.05 MB；可继续拆分组件依赖，并在反向代理开启 JavaScript/CSS 静态资源压缩。当前 Node JSON 压缩已生效，图片无需重复压缩。
- 部署后需再实测服务器网络和资源占用。本次没有服务器 SSH 或运维面板访问，未验证 CPU、内存、磁盘及进程管理配置；付款、签署、派车等有业务后果的操作也未在线提交。
