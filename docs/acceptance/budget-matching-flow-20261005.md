# 总预算与业务流转样式验收

## 实现

- 求解条件按路线、货物与运输安排、总预算分组，支持地图选点和一行两端地址。
- 新增 `minBudget` / `maxBudget`，表示整单总价，单位元，可不填写或只填写一侧。前后端校验下限不超过上限，范围0至20000000元，两位小数。
- 求解服务在推荐、排序及保存前筛选完整的全程测算费用；费用不完整的路线不能确认满足预算，单独计数提示。预算保存在本人求解记录的输入中，沿用现有主体权限；发布快照采用明确字段，不包含预算区间。
- 用户界面、提示和新审计文案统一使用“邀约议价”；枚举 `DIRECTED` 保持现有协议。邀约企业可多选。
- 大厅的需求、供给、我的三项页签采用居中等宽布局，图标和选中背景共同标识当前页。
- 运输需求、匹配、合同、联运服务及跟踪、账单和结算使用统一状态组件。浅暖色表示待处理，浅蓝色表示流转中，浅绿色表示完成，浅红色表示需要关注，浅紫色标识邀约。卡片和主列表行增加对应浅色背景，合同号、运单号和发布编号加强字重。
- 手机条件区单列，大厅筛选双列，卡片企业名及操作按钮分行。

## 验证

- API TypeScript 编译及前端 vue-tsc / Vite 构建通过。存在原有组件包体积提示。
- `node tests/planning-budget.cjs`：元/分转换、两端边界、单边预算、不限、零上限、未知费用、不合法金额、逆序区间、服务提前拒绝均通过。隔离内存数据进一步验证求解在保存前筛选预算、保留输入及无结果提示。
- `node tests/planning-recommendations.cjs` / `node tests/planning-network.cjs`：原有推荐和线路约束通过。
- 浏览器验证三项大厅页签、卡片/列表切换、邀约多选入口、预算输入纠错、合同履行状态及运单背景。
- 390px手机宽度下，页签完整、预算字段和卡片操作无横向溢出；已恢复浏览器默认尺寸。
- 当前贸易方账号的账单列表为空，确认空状态正常；账单状态组件通过类型及构建检查。
- 验证未新建、发布、签署或完成业务单据。
