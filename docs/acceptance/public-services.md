# 需求带入与公开班线验收

日期：2026-10-01。

范围调整：用户要求暂不继续精确地址匹配，本轮停止扩展此项，保留基础地址带入和人工确认选点，交付重点为公开班线与联运求解。

## 修复结果

- 浏览器复现：需求详情跳转后地址只作为搜索提示，`origin`、`destination` 仍为空，点击求解出现“请填写：起运位置、目的位置”。
- 服务端按同城、同名的有效节点或唯一高德 POI 自动定位；不能精确匹配时保留原地址，明确显示待定位，打开定位窗口自动搜索。搜索结果在地图展示，必须确认后使用；没有把区县中心当作仓库位置。
- 来源货物、数量、装载与发运约束仍锁定；方案保存来源快照，刷新后恢复需求业务编号和限制。需求抽屉关闭事件不再操作其他业务页面的 URL。
- 高德 `serviceHost` 改为规定的根路径 `/_AMapService`，仍转发到受登录会话和路径白名单保护的服务端代理。浏览器确认当前 Key 在 `127.0.0.1` 可用，而 `localhost` 报 `INVALID_USER_DOMAIN`；Vite 开发环境统一跳转到前者。生产部署须按正式域名配置高德授权，并将 `/_AMapService/` 转发到 API。

## 求解规则

- 公开班线未取得价格也可形成候选。未知干线费用返回 `null`；完整费用返回 `null`，另提供已知区段费用小计。缺少完整价格或排程的候选不参与完整价格推荐。
- 船运资料未公布里程：数据库兼容列存0表示未填，响应转换为 `null`，页面显示“里程待核验”；不能据此按吨公里算出零元干线费。
- 干线时长采用上述公开口径，候班、装拆箱及未核实作业时间未知；完整到达时间返回 `null`，界面明确待确认。没有编造当前船期或保证到达时间。
- 散装货物仅在“散粮入箱比选”开启且允许联运、中转时，纳入集装箱班线。结果标明装拆箱能力、费用、箱数与粮食承运条件待确认。关闭后排除这些候选。
- 起终点到港站的公路接驳调用正式高德道路服务。铁路、海运尚无已核验轨迹，地图仅显示相关节点；完整衔接在方案区段链中呈现，没有用直线或公路冒充干线。
- 公路参考单价仍是原有开发样例。选择完整方案只保存比选结果，不等同订舱、报价承诺或下发运输任务。
