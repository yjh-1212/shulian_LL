# 供需匹配大厅：我的发布与双向推荐

验收日期：2026-10-02。

## 使用流程

- 需求大厅和供给大厅用于浏览有权限看到的发布信息。
- “我的”按发布账号列出自己的需求、方案或运力供给，展示私人匹配摘要和推荐值。
- 贸易商从推荐运营商发起邀请，邀请沿用原发布和运输数量；也可以在供给大厅选择本人已有发布邀请运营商。
- 物流运营商从本人的运力推荐进入适配需求，可提交报价或查看自己的既有报价。
- 发布匹配入口位于“我的”。指定议价可选择 1 至 10 家企业，共用一条发布记录；各企业独立报价。
- 货主可比较收到的报价，再走既有议价、接受条款、承运确认、合同流程。完整方案须整程承接，多个受邀企业不重复占用运输数量。

## 权限

| 信息或操作 | 发布账号 | 报价账号 | 其他贸易商/运营商账号 |
| --- | --- | --- | --- |
| 有效公开供需信息 | 可见 | 可见 | 可见 |
| 指定议价信息 | 可见 | 指定企业的账号可见 | 非指定企业不可见 |
| 我的发布和匹配推荐 | 仅自己的 | 仅自己发布的运力推荐 | 不可见他人的推荐 |
| 报价与议价记录 | 可见本发布收到的报价 | 仅自己的报价 | 不可见他人的报价 |
| 邀请、关闭、确认、取消承运 | 本发布账号按角色权限操作 | 本报价账号按角色权限操作 | 不可越权 |

以上限制在接口执行，同一企业的其他账号也不能读取私人推荐或他人的报价。平台的既有审核只读权限保留；平台不能代替业务方报价或确认承运。

## 推荐依据

先筛选实际有效发布：起讫省市覆盖、粮种、装载形式、待运输数量、运输方式和服务窗口。方案来源需求使用已选方案的分段和装拆箱条件。

需求推荐运营商综合路线匹配、发布运价、有效接单记录、企业注册地评分，并按企业去重。运力推荐运输需求综合路线、条件适配、贸易企业的运输落实记录及注册地评分。缺少报价显示待协商；集装箱按实际箱数或带提示的模拟装载量换算。参考价不自动成为成交价。

暂停、失效、截止或运输数量已落实的信息停止推荐。匹配列表展示最多 10 个候选，服务和价格仍需双方确认。

## 已验证

- `npm run test:matching`：双向推荐、账号隔离、同企业越权拦截、邀请幂等、指定多选原子校验、独立报价、承运确认和暂停供给。
- `npm run test:planning`：联运求解、供应商推荐、多企业发布和共用运输数量。
- `node tests/phase4.cjs`：公开/指定权限、多轮议价、分量匹配、并发防超配、关闭和重新匹配。供给搜索断言改用业务编号，适配此前供给名称改为企业名称的需求。
- `node tests/phase3-fresh-db.cjs`：全部迁移在独立新库部署，重复初始化及 8 家模拟运营商、32 条供给。
- 前后端类型检查、生产构建通过。
- 历史业务记录、订单占用数量及历史报价条款保持一致；报价作者按原始报价轮次回填，数据库无外键错误。
