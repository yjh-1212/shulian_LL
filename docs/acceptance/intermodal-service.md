# 联运服务验收

## 页面与操作

- 联运管理仅保留“联运服务”，旧菜单地址自动跳转到运单列表。
- 合同生效后自动生成总运单，以合同号生成对应运单号。列表支持运单 / 合同号、双方企业、计划发运时间、起运地、目的地、货物类型和进度筛选。
- 主页面展示总运单，展开后展示运输阶段，再展开展示车辆任务、船舶或铁路信息；阶段详情为只读。
- 物流运营商点击“开始跟踪”打开独立地址 `/services/:id/tracking`，选择阶段填写公路、水运或铁路信息，保存、提交、上传附件、确认阶段完成以及登记对账费用。阶段允许并行执行。
- 每行“发运甘特图”按钮展示整个运单，按公路、铁路、水运阶段分组。公路每辆车独立展示车牌、司机、数量、各自计划时间及任务进度；保存的车辆草稿也可展示，提交后切换为司机任务，完成后提供实际完成时间提示。多辆车全部展示并支持滚动；同车多趟显示任务数。
- 右上角保留批量“业务完成”：选择满足完成条件的运单，核对费用并提交，每个总运单生成一张未对账账单。
- 贸易商与平台仅查看；运营商仅维护本企业承运的运单；司机仅查看自己的任务和回传资料。

## 业务链路

公路阶段提交后按车辆生成司机任务。司机在独立模拟端接收任务，上传散货磅单或集装箱设备交接单，填写铅封号（集装箱）、签收数量、签收人及签收单；费用按船公司放单费、港口杂项作业费、清箱费与其他杂费回传。

水运支持多箱号、散货过磅与散改集；铁路记录铁路运单号、发站、到站及计划时间。运营商确认阶段完成后可登记其他费用及说明，勾选司机、阶段与合同费用进入总运单账单。合同费用按总运单计入一次。

业务完成以同一事务写入账单与运单进度，失败时整体回滚；重复提交不会重复生成账单。完成后的运单与关联费用锁定；费用差异沿用双方对账流程，禁止伪造或重复费用来源。

- `intermodal-service-browser.json`：独立跟踪页、菜单式展示、阶段操作、附件回显与整单甘特图通过浏览器验收。

- `intermodal-preservation.json`：与改造前备份比较，19 张原业务表的既有数据和附件字节保留。
- 前后端类型与生产打包检查通过。
- 浏览器验证新页打开、草稿保存、阶段提交和完成、水运散改集多箱号、新阶段附件上传与重新打开后回显、只读列表详情；此前已验证司机接收、凭证与费用回传、运营商阶段完成、费用勾选及未对账账单生成。

所有验收数据为本地模拟数据，不代表实际运输、签章或资金结算。

## 数据库更新

部署时先备份，再执行 `npm run db:migrate` 和 `npm run db:generate`。既有生效合同可执行 `npx tsx tools/backfill-intermodal.ts` 补齐运单与运输阶段；此操作可重复执行，保留既有任务、凭证和账单。新生效合同自动生成运单。
