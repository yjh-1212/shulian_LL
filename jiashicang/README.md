# 辽粮数智联运驾驶舱

## 入口与运行

独立入口为 `/cockpit`，直接打开即可查看，不需要登录，也不需要创建账号或分配权限。

首页导航与登录后平台顶部主导航均提供“驾驶舱”入口，点击直接进入平台运营大屏，可在大屏内切换“一粮一链”。平台导航在宽度不足时仍保留“驾驶舱”按钮。

- 平台运营：`/cockpit?view=platform`
- 一粮一链：`/cockpit?view=chain`
- 综合驾驶舱：`/cockpit?view=comprehensive`
- 粮源分析：`/cockpit?view=grain-source`

### 综合驾驶舱

新增独立蓝色风格，复用同一套中国地形、省界与右下角南海附图。左侧为通道总体态势、今日运行概况、运输任务执行；右侧为通道运行态势、重点节点态势、今日预警。六个侧面板背景透明，折角蓝色边框。地图保留受控的蓝色边缘流光、节点呼吸与底座光环，提供动效暂停。

所有新增业务数字是静态前端展示数据，保存在 `src/comprehensive-data.ts`，没有新增数据库业务记录，也不轮询业务统计接口。粮源区、接收区和节点坐标是地理参照，不代表实车、船舶的当前位置。北方可组织粮源为 7,450 万吨；四个明确接收区合计为 7,000 万吨，其余 450 万吨尚未分配接收区域。今日在途批次含跨日任务，与今日计划的执行中任务属于不同口径。

`map_data/comprehensive-network.json` 包含 8 条地理参考通道：既有 OpenStreetMap 铁路、公开 OSRM 道路参考和 Marnet 海运网络。道路保留真实弯折；沿海航路由公开网络求路，不补画港区接驳直线。不表示实际发生的轨迹，也没有调用高德付费路径接口。新增 OSRM 原始查询缓存位于 `.local/comprehensive-reference/`，构建脚本为 `tools/build-comprehensive-network.cjs`；生成后的本地 JSON 随前端构建打包，打开驾驶舱不请求外部路线服务。来源入口保留在“图层”面板。

区域卡片、重点节点与预警可选中并高亮通道；公铁水图例与运行概况可切换线路图层；重置恢复全国总览。WebGL 不可用时降级为二维地图。仅检查桌面大屏布局。

综合驾驶舱风格单独保存并参与原有跨浏览器同步。读取旧版设置时自动补齐新增驾驶舱的默认风格，保留原有已保存设置。风格设置可应用至全部四个驾驶舱，也支持“通道蓝”和“暖金粮源”预设。

### 粮源分析

根据根目录《粮源分析.docx》开发，参考 demo1 的暖白、金橙、地形纹理、白色立体侧面与受控扫描动效。中央区域地图仅包含黑龙江、吉林、辽宁和蒙东四盟市（呼伦贝尔、兴安盟、通辽、赤峰），采用七个互不重叠的真实行政边界。省份标记使用省会、盟市标记使用行政中心，表示统计区域，不表示具体粮库位置。未改动原有全国地图与南海附图。

使用统一的 **2025 完整年度官方总量统计**，并保存七地区 2023—2025 历史。数据和二十条官方来源在 `map_data/grain-source-statistics.json`；总产量合计 18,275.54 万吨、面积合计 2,931.771 万公顷。省级总量采用国家统计局公告，分品种和盟市统计采用地方公报。未公布的原始分项保留 null，展示层仅用单独的 `grainEstimates` 补足主粮矩阵；没有编造实时库存、可外运量或未来预测。同比、合计、单产与增产贡献由公开值计算，可能受各年初步数据和四舍五入影响。页面“数据来源”可查看实际口径、来源链接、估算公式和不确定性。

县域热力层接入 `BLNY_MVP/BLNY_mvp_ZF/data/grain_sources_northeast_demo_with_coords.json` 的 132 个行政中心点，副本为 `map_data/grain-source-points.json`，原项目许可保留在同目录 `.LICENSE`。核心 39、重点 68、一般 25，沿用目录分类而非官方产量排名。热力为固定带宽核密度叠加，5/4/3 等级映射为 1/.6/.28 权重，统一除以 1.15 进入固定色阶，不因筛选重新归一化；按行政边界裁切。点位和核心呼吸环采用实例化绘制，筛选时才重建热力纹理，离开页面释放。支持地区、粮种、等级筛选、县域详情及区域产量图层切换；县域目录无产量数据，不向点位分摊省市总产量。

主粮补项：吉林大豆官方 17.36 亿斤换算 86.8 万吨；赤峰玉米约 546.8、稻谷约 11.6 万吨，按 2023 年品种份额乘 2025 年粮食总量；赤峰大豆约 12.4 万吨，假设 2023 年豆类中 90% 为大豆后同比例外推；呼伦贝尔稻谷约 11.1 万吨，假设总量扣除已公布玉米、大豆、小麦及马铃薯后的余量中 60% 为稻谷。后两项假设较强，不能作为正式统计结论。所有估算以“≈”显示，悬停及来源抽屉公开公式；不改动官方总量与历史序列。

左右各三个透明面板：粮源生产总览、主产区规模分布（矩形树图）、主粮品种构成（矩阵）、播种面积与产出（气泡散点）、地区增产贡献（瀑布）、地区产量变化（指数哑铃）。默认矩形树图先汇总黑吉辽和蒙东，点击蒙东可展开四盟市；其余图保留七统计单元。地区筛选、地图标签、图表与总览联动，选择地区后仍保留其他地区作为对比。地图可旋转缩放、控制产量晕圈、暂停和复位；无 WebGL 时使用可操作 SVG 地图。

新增源码为 `src/components/GrainSourceCockpit.vue`、`GrainSourceMap.vue`、`GrainSourceChart.vue`，以及独立的地图引擎、统计映射、图表选项和样式。ECharts 和本页按需加载，打开原有两个驾驶舱不会加载粮源统计图表。数据保存在前端文件，不修改业务数据库，也不在浏览时请求外部统计网站。

本地验收：`node --test jiashicang/tests/grain-source-data.cjs` 验证边界与统计区域一致、来源完整、三年覆盖、缺项、单位与汇总；`jiashicang/acceptance/grain-source-20261015/` 保存桌面浏览器检查和截图。

粮源地图表面采用高德卫星影像：`map_data/grain-source-amap-satellite.webp`，来源、获取时间和 Web Mercator 范围保存在同名 JSON。72 张 zoom 7 切片组成 2048 × 2304 纹理（约 1.2 MB），随前端打包，无浏览时外部瓦片请求。使用自然色无光照顶面材质，光照仅作用于立体侧面，避免灰白去色和过曝。关闭纹理后仍使用风格设置中的区域颜色。页面保留高德来源署名；该影像不是实时遥感，获取时间不代表拍摄时间。

如需更新影像，运行 `python jiashicang/tools/build-grain-satellite.py`（依赖 Pillow 和 curl），确认预览后重新构建前端。切片缓存位于 `.local/grain-satellite-tiles`；构建脚本在所有切片下载成功后才替换纹理。

全国地图统一使用 `map_data/china-amap-satellite.webp` 高德卫星影像，144 张 zoom 6 切片组成 3072 × 3072 纹理（约 1.6 MB），精确范围与来源记录在同名 JSON。运行 `python jiashicang/tools/build-grain-satellite.py --national` 可重新生成。平台运营、通道运行默认关闭影像，一粮一链、综合驾驶舱、粮源分析默认开启；风格设置中的“显示高德影像”仍可预览、保存并同步。影像顶面保留自然色，业务区域只叠加轻微色调，路线、节点、立体侧面及南海附图保持独立。旧的 `china-terrain.webp` 已不再被地图引擎引用。

驾驶舱接入现有 Node.js 服务和数据库。正常运行本项目后，可访问 `http://127.0.0.1:5173/cockpit`。使用 `SERVE_WEB=true` 的服务器部署方式时，访问服务器地址后加 `/cockpit` 即可。

统计展示接口为公开、只读接口：`GET /api/cockpit/overview`、`GET /api/cockpit/chains/:id`。风格设置接口 `/api/cockpit/appearance` 公开读写，只修改共享外观和预设。其他业务接口继续使用系统原有登录机制，凭证只展示元数据。

## 页面设计

采用用户保存的蓝青与金穗两套风格。中国三维统计地图在桌面上覆盖整屏，顶部和左右各三个透明面板叠在地图之上，地图放大后可以延伸到面板下方。六个面板使用折角细边框和标题短线。顶部仅保留紧凑的驾驶舱页签、时间和操作按钮；两侧面板从顶部栏下方延伸到页面底部。面向桌面大屏设计与验收。

| 驾驶舱 | 左侧三个区域 | 右侧三个区域 |
| --- | --- | --- |
| 平台运营 | 业务规模与趋势、多式联运结构、供需协同情况 | 履约与运输效率、风险预警分布、费用与结算统计 |
| 一粮一链 | 粮种运输结构（环图）、主要发运地区（矩形树图）、粮食联运链条（桑基图） | 主要到达地区（立体球图）、粮食运输通道结构（热力图）、运输规模与合同单价（散点图） |

支持地图左上方的时间范围和粮种筛选、一粮一链地图右上方的粮种分类、地图缩放旋转、手动刷新和全屏。两个 Tab 使用同一份聚合数据和同一个地图实例，不再逐单读取任务、凭证或位置。前台每 60 秒更新；隐藏页面或打开风格设置时暂停自动更新。

## 大屏风格设置

右上角设置按钮打开可拖动的参数面板，修改后实时预览，取消恢复修改前状态。

1. 整体主题与背景：背景主色、渐变、主题色、强调色。
2. 文字与指标：正文和辅助颜色、字号、指标数字、字体风格。
3. 面板与布局：背景、边框、透明度、圆角、阴影、侧栏宽度和间距。
4. 图表：配色、线宽、网格。
5. 地图：地形纹理、区域和侧面颜色、边界、立体高度、视角、光照、底部网格。
6. 线路与运输资源：公铁水颜色、粗细、总览线路数量、节点名称、标签数量和字号、运输资源显示。
7. 动效与性能：线路流光、节点呼吸、边缘流光、扫光、速度、渲染模式、进入页面自动巡航。

默认参数来自用户在 2026-10-09 截图中使用的两个风格，完整保存在 `server/default-styles.json`。新浏览器读取服务器最新风格，旧浏览器本地设置不再覆盖共享值。

包含深海联运、金穗流转、清朗浅色、流畅展示四个内置预设，可另存最多 12 个共享自定义预设。同名另存会更新原预设；选择自定义预设后可用旁边的删除按钮移除，当前已应用的风格保持不变。内置预设不删除。

两个驾驶舱分别保存风格，也可勾选应用到两者。参数修改仅在当前浏览器预览，点击“保存风格”后写入服务器 SQLite 数据库的 `CockpitAppearance` 表，其他已打开的浏览器约 5 秒内同步。隐藏页面暂停同步，返回页面时立即读取。其他浏览器的更新保留当前编辑预览，取消会显示最新共享风格。并发保存通过版本检查防止覆盖未读取的设置；失败保留预览并提示重试。服务重启保留共享风格和预设。

风格接口不需要登录，沿用驾驶舱独立公开入口的设置范围。代码更新首次使用时会创建所需的独立配置表，后续正常迁移也会保留此表。没有新增业务数据。

## 数据来源与口径

**没有写入或新增数据库业务记录。** 根据用户要求，缺少的展示数据只在前端 `src/display-data.ts` 中补齐，不在页面增加额外标记。

前端补齐范围：不足四个有数据月份的运输量与供需趋势、缺少结算分布的费用趋势、只有单一分类或无记录时的风险分类。趋势分布是展示构造，不是实际月度成交或结算记录。运输量、需求和匹配数量优先保留系统总量；缺少结算数据时以合理比例构造已结与待结，面板数字与图表来自同一展示序列。范围完全无业务且无需求时保留空状态。

数据来自系统既有的运输需求、供给、合同、联运业务、运输阶段和任务、位置、风险、预测、凭证元数据及账单。排除 `isTestData=true` 的记录。

本次检查的数据库数据包含 16 笔联运业务，四种粮种为玉米、大豆、小麦和稻谷，计划运输量合计 17,381.1 吨。**这 16 笔来自系统此前生成的 `BUSINESS_INITIALIZATION` 待核验记录，不能当作已核实的真实成交或实时运输数据。** 数据来源保留在聚合接口中，驾驶舱按照本次要求只展示统计内容。

- 运输量：每笔业务只累计一次，不因包含多个运输区段而重复累计。
- 已完成业务量：按业务的完成状态统计计划数量，不等于经签收确认的交付数量。
- 账单 API：仍返回原始账单与实际已结金额；前端展示补齐不会改变业务结算模块。
- 合同单价：合同金额 / 计划运输吨数；不是实际交付单位成本。
- 运输网络：将业务区段匹配到独立的地理参考文件，按真实折线绘制；没有可核验线路的区段留空，不用起讫直线补齐。
- 一粮一链：汇总各粮种的发运地区、到达地区、联运方式与业务状态；桑基图各层运输量守恒，热力图每单只归入一个联运组合。
- 省份高亮按发运、到达区域的关联运输量调整强度；流光和节点呼吸表达运输网络，不表示当前实车或船舶位置。

## 地图交互与路线回放

- 全国总览保留主要线路和有限标签；公路为实线、铁路带横向刻度、水运带虚线，颜色沿用共享风格。
- 点击线路、节点或省份查看关联运输量、业务数量、区段和来源；“聚焦”平滑调整视角。点击地图仅高亮，不改变统计口径。
- “筛选此通道 / 节点 / 地区”会明确缩小左右统计范围。运输量、合同、需求引用和账单使用同一范围；关闭范围标签恢复全局。
- 粮种环图、发运树图、到达球图、通道热力图、联运桑基图、业务状态和风险分类可联动地图；粮种选择同时筛选统计。
- 图层提供联运网络、发运分布、到达分布、风险节点，以及公路、铁路、水运的独立开关。
- “路线回放”沿各区段的累计地理距离推进，切换公路车辆、列车和船舶，支持暂停、继续、进度拖动、倍速、重新播放。区段间短暂停留，未核验接驳段隐藏资源标记并显示衔接状态。
- 回放是沿参考线路编排的可视化过程，**没有实际车辆历史 GPS、船舶 AIS 或运输时间含义**；不产生定位记录、不改变任务进度。页面不使用“演示”“模拟”文字，也不将该过程命名为实时定位。
- 巡航默认关闭，可手动开启，也可通过共享参数设置自动巡航；鼠标拖动、滚轮、手动选通道或进入设置时停止巡航。Esc 清除选择和回放，恢复总览。

### 地理参考来源

`map_data/transport-network.json` 包含 10 个登记节点与 10 段道路、铁路和海运参考线路，统一为 WGS84。网页加载一次此文件，筛选和回放无需重复请求路线服务，也不调用付费路径接口。

| 类型 | 来源与范围 |
| --- | --- |
| 公路 | 系统已有 [高德驾车路径](https://lbs.amap.com/api/webservice/guide/api/newroute) 缓存。保留道路转弯；属于道路参考路径，未核验货车限行、轴重或车型限制。 |
| 铁路 | 系统已有 [OpenStreetMap 铁路基础设施](https://www.openstreetmap.org/copyright) 线路；保留公开轨道走向，去掉原数据附加的未核验站场接驳点。© OpenStreetMap contributors，ODbL。 |
| 水运 | [Marnet / searoute-py](https://github.com/genthalili/searoute-py) 公开海运网络，以现有网络边求最短路线；上游为 Eurostat SeaRoute / ORNL 航运网络。不能用于船舶导航，也不代表特定船舶的历史航迹。 |

海运文件固定到 `tools/reference-data/source.json` 中的提交版本。鲅鱼圈港至公开网络起点约有 39.8 km 接驳缺口，南沙港约 6.2 km、新沙港约 18.0 km；这些缺口不绘制线路。铁路站场接驳缺口也保留。详情的“路线来源”提供各段来源、口径和未包含距离，图层设置保留数据署名。

只读重建命令：`node jiashicang/tools/build-network.cjs`。命令读取现有业务快照和路线缓存、执行坐标转换与最长 25 m 偏差的折线简化，只写地理参考 JSON，不创建业务数据。水运网络保留原始边，禁止生成直线港口接驳。

## 地图与性能

- 地形使用用户提供的 `map_data/100000_z7.png`，保留原文件；转换为 2048 像素以内的 `china-terrain.webp`，从约 24.6 MB 压缩到约 378 KB。
- 省级边界来自 [DataV 中国地图边界](https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json)，存为本地 GeoJSON。
- 地图使用 Three.js，主图保留台湾与海南本岛。南海诸岛与断续线集中在地图区域右下角的透明附图，固定位置，不随主图缩放或旋转。断续线完整使用用户提供的 GeoJSON，保存在 `map_data/nine-dash-line.geojson`；原文件内的十组线段全部保留。
- 使用本地资源，驾驶舱不加载高德在线地图或请求地图 Key。
- 两个 Tab 共用一个地图实例。离开页面时释放 WebGL、纹理、几何体、监听器和定时器。
- 回放仅更新资源位置和方向，不重建线路几何体；鼠标拾取限频，路线采用宽容点击区域；标签只出现在地图可用区域并避免碰撞。
- 主地图、节点与线路整体向下偏移屏幕高度的 8.5%，三维与二维视图使用同一偏移量。
- 均衡模式限帧，流畅模式降低像素比和动效；尊重系统减少动态效果设置，页面不可见时停止渲染。
- 无 WebGL 的设备自动使用二维地图，继续展示业务线路与节点。
- `reference/sc-datav-main.zip` 作为效果与交互参考，未将完整参考工程加入生产页面。
